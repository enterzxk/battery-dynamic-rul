# Full188 DataV2 continuation protocol

This is a candidate execution package only. It is not a GO. The two-sample pass and exact member outputs are prerequisites; no full-scope GET, decompression, or fit has occurred in this branch.

The frozen scope is `reports/isu_ilcc_datav2_full_20261020_root/scope_candidate.json`, SHA256 `1dfd1a4be9fbba2f2ce5998689358e375856bf8595b7b6fd05d153b20dd4be5a`: exactly 188 unique train/development members (125 train, 63 development), zero locked. The remote receiver checks every scope member against central-directory offset, CRC, compressed size, uncompressed size, flags and method, and checks exact cohort ID/role membership and byte totals. The scope totals 703,318,560 compressed bytes and 5,399,141,926 uncompressed bytes; largest member expands to 118,703,961 bytes. It carries 5 already-consumed GETs and 12,404,109 response bytes (the successful two-sample 4 GET/12,404,079 B plus one retained 30 B metadata-header failure), leaving 372 member-range GETs under the total 377 GET limit. G1C1/G20C1 outputs are reused.

`isu_datav2_full188_once.py` is the Windows controller; it reads each HTTP response into memory and streams it directly to the remote `full188_receiver.py`. The remote host makes no network request. SSH command arguments are shell-quoted individually. Each not-yet-saved member uses exactly two ranges: 30-byte local header, then filename+extra+central compressed bytes. The controller checks status 206, exact Content-Range, ETag and Content-Length before reading at most requested length+1. Raw range bodies are retained only on the server. The controller runs one worker, below the two-worker ceiling.

Before reading, the receiver requires its own fresh full-scope delta PASS and GO. GO binds the exact scope, controller, receiver, unchanged two-sample parser, protocol, cohort JSON, central receipt and archive scope hashes; source archive ID 43756491, 929,406,930-byte length and ETag; owner and coordinator-lock hash; prior GET/body totals; and caps of 377 total logical GETs (5 already consumed, 372 new), 704,000,000 total response-body bytes, 5,399,141,926 uncompressed bytes, 3,600 seconds, 2 maximum workers, zero locked reads, zero fits, and no training. The receiver checks owner/cwd/takeover/heartbeat and lock before claim and during every operation, and creates a per-GO claim with exclusive file creation.

The append-only member ledger records a conservative response-body reservation before every GET. Reservations count against future GO budgets even if a request or transfer fails. A new explicitly authorized GO can resume from saved exact ranges or completed outputs; its `prior_logical_gets` and `prior_network_body_bytes` must equal the completed two-sample totals plus all previous full-run reservations. Same-GO retries are rejected. Existing G1C1/G20C1 outputs are validated and ledgered as reused, with no network refetch.

The receiver imports the unchanged parser from `reports/isu_ilcc_datav2_two_sample_repair_20261020_root/prepare_datav2.py`. It produces create-only per-cell contracts and a create-only scope manifest. The append-only ledger records completed/reused cells and exact source hashes. It finalizes only when all 188 outputs exist with 125 train and 63 development roles, then writes a create-only inventory. Observations remain indexed by original RPT list position; missing values remain missing; capacity is visible only at observed stop; calendar age derives only from observed stop timestamps. RPT position and cadence do not create cycle/EFC values. Only valid rows can be marked as first observed capacity <=0.20 Ah. Latent EOL and censoring stay unknown.

Failures retain partial server-side ranges and create one failure receipt per GO; they stop the current attempt without automatic retry. The full GO has not been issued or consumed. The independent root review and a fresh exact GO are required after the two-sample task is accepted. This package is intentionally separate from the two-sample receiver/controller and never modifies their source.

## Lossless timestamp parser version2
At G35C1, Python3.9 rejected official nine-decimal timestamp strings. Only a final000 after six fractional digits is removed for parsing; original strings remain untouched. This is exactly lossless at microsecond precision, no interpolation/imputation. Nonzero sub-microsecond suffix remains unsupported and stops. New parser_ns_v2.py is separately hashed; prior parser/GO/failure remain. Resume reuses G35C1 saved compressed ranges and all completed outputs; no extra GET/body budget.
