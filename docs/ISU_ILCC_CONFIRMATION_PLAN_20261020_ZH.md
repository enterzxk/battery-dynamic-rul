# ISU-ILCC 独立确认方案与开发选择规则

状态：在首轮新数据开发指标产生前冻结的方案；不是训练或确认读取许可。

1. 新队列按来源电芯ID冻结为C1/C2训练125、C3开发63、C4确认63。C4容量/曲线payload保持封存；ZIP目录元数据已知不算轨迹读取。当前无预训练模型参与。来源ID隔离已建立，物理serial未独立核实，报告按来源ID留出，不声称已核物理身份或跨域泛化。
2. 单位为原始RPT完成日期相对首个观测完成日期的日历周。真实cycle/EFC及持续运行时长仍未知。事件为来源可用RPT首次实际观测Q<=0.20Ah的完成时刻；不等于潜在物理首次越阈。原始、每2个原始RPT位置保留、延迟7日，使用同一来源事件和共同查询时刻。信息隐藏不声称改变物理实验日程。
3. 首轮点RUL仅评价有精确来源事件的pre-event共同origins。非事件资产保留并列出停测未知，不伪造独立右删失。只有pre-event评分不能证明未知事件状态的校准：提出概率可靠性主张前，须先在开发数据实现并冻结完整来源查询窗至记录末，使用max(T-query,0)，分别处理健康检查到达和独立告警可见性。不能免费按仍运行进行生存条件化。
4. 开发选择先以三种观测设置等权的电芯宏平均MAE选定最强简单基线（group prior、早期健康HGB、动态HGB、统计AFT）；GRU与固定融合另列，仍必须报告与全部方法的比较。方法选择不按单颗电芯或某一优胜场景挑选。
5. 候选保留的预定开发门：相对最强简单基线的三场景宏MAE至少降低5%；任何场景严重高估(>4周)率不增加超过1个百分点；任何场景IS80不恶化超过5%；不能只依赖少数电芯平均收益，列出逐电芯变化及MAE恶化>2周的比例。以上为实用筛查门，不构成统计显著性或投稿保证。配对电芯bootstrap区间跨零时明确标为不确定；不通过则保存NO_GAIN，不用确认集救援。
6. 若解释长期/短期分解，参数必须通过预先冻结的收敛、边界和Hessian可识别性门；失败不把近似状态解释成已识别物理量。过滤与普通Kalman均用相同可见信息、原始特征、HGB头与电芯权重，OOF所有参数在各训练折内估计。
7. 首轮seed42为开发试验。随机神经基线若影响方法选择，需在封存确认前按固定13/42/77补足训练稳定性；确定性的CPU状态模型/HGB不将重复相同结果冒充独立seed证据，需检查实际随机来源及固定折分/电芯抽样敏感性。每项新增拟合仍需独立具体GO和保留预算。
8. 正式确认前冻结方法、全部源代码/协议/训练数据变换/参数与checkpoint SHA、选择规则、观测设置、查询和端点规则、全部指标以及比较对象。默认使用仅125训练电芯得到的已保存模型；开发63不得临时并入重训。经独立窄审和fresh exact确认GO后，C4只评估一次，不调阈值、尺度、窗口、权重或模型。确认结果失败也公开保存，不能再次选择后包装独立确认。
9. UConn-ISU-ILCC LFP/Gr为第二体系候选，目前仅官方元数据可行性；README访问和EOL分母/时间字段待核。不得将其循环/EFC/日历单位强行映射为本体系。来源、处理和协议合法后另冻结角色与GO。
