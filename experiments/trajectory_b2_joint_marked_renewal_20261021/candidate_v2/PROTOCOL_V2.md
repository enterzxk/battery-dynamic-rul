# B2-v2 joint marked-renewal candidate — preparation only

Status: static code/protocol review candidate. No train payload read and no fit is authorized by this package. The earlier three-component GMM design is preserved under `legacy_gmm_unfit/` and is not the main candidate.

## Estimand and observation

The event remains the first valid source-RPT capacity at or below 0.20 Ah, with `R_q=max(T*−q,0)` and a point mass at zero when the event has already happened by query time, including an event seen only in a not-yet-arrived report. This is source-observed threshold time, not latent physical EOL. Unknown post-window tails remain unidentified; no fabricated administrative-censor likelihood is allowed.

At each legal as-of query, select the last VALID source RPT that has arrived by actual q. Build the fixed context at that anchor's source epoch: (a) the frozen V18 `_feature_view(cell, visible_records, encoding_epoch=anchor_source_epoch)` 74-vector, with explicit missing mask, and (b) the latest three arrived valid RPT source-feature records from the frozen F1 RPT asset, with per-feature missing masks, source-index/time offsets from the anchor, and record-presence masks. First check actual `arrival_epoch<=q` for every included record. Encoding at anchor source epoch avoids declaring an arrived delayed report to have been known earlier; actual q remains a separate visibility gate and elapsed-since-anchor input. No cycle features, future operations, query labels, or C3/C4 data enter the fixed input.

Keep the fixed anchor embedding unchanged through simulated hidden/future checks. A separate dynamic state is updated only from the observed or sampled marks: current capacity, last valid-RPT gap, last signed capacity increment, elapsed time from anchor, generated step count, and cumulative source-index progress. This lets the process age as gaps and capacity increments are sampled without inventing future raw RPT curves.

## Mark density and forecast

For each transition, model `log(gap_weeks)`, signed `delta_log_capacity=log(C_next/C_current)`, and categorical source-index jump ΔK∈{1,2,3}. All source capacities must be positive. This permits recovery while ensuring sampled capacity stays positive without a clipping rule; the threshold event remains measured C≤0.20 Ah. A small MLP64 with 3 mixture components is a density estimator, not an architecture sweep. The joint variant uses a bivariate Gaussian for log-gap and signed capacity increment plus component-conditional ΔK probabilities. The independence control uses the same network/head and the same marginal component distributions but samples gap, capacity increment, and ΔK independently. It is an explicit product-of-marginals control; report identical configured parameter counts and disclose the covariance-coupling ablation.

Train on teacher-forced suffix transitions from multiple legal anchors across the 125 train-only reviewed processed paths. At each anchor, the fixed context uses only the legal visible prefix. Augment raw and sparse2 prefixes using the exact frozen `_arm_records` retention rule, including the second-valid-RPT warmup exception and parity relative to that source index. For each cell, each arm/anchor path receives equal mass; within a path, suffix steps receive equal mass. Sample rows proportional to these fixed weights and optimize the unweighted batch mean, so weights are not accidentally applied twice. Train an internal cell-isolated selection fit and refit each of the two variants on all 125 train cells: exactly four neural fits total (two internal fits + two full-data refits), seed 42, batch 256, at most 3,000 optimizer steps per fit. Do not use C3 for selection. No held-out data are read during preparation or fit.

For a query forecast, generate positive gaps by exponentiating the modeled log-gap with no clipping that changes the density. Continue latent paths through q and apply the exact arm retention/arrival rule. Reject paths containing any extra valid report that should already have arrived by q but is absent from the visible prefix. Sparse2 checks at nonretained source indices are not contradictions. Delay7d separates source stop and arrival; an event can be before q while its report is still delayed, yielding R=0. Continue paths after a hidden crossing through q to test later no-extra-arrival constraints. After conditioning, simulate until the first valid capacity threshold event or 128 weeks; report event mass at zero, proposal acceptance, effective sample size, and `tail_gt_128`. Apply the same 128-week support to direct F1 RUL comparisons. No actual future source grid or operation inputs are used.

The training suffix continues through the end of the observed valid-RPT source window, including after the first threshold crossing. This supports the no-extra-due-report filter when a simulated hidden path crosses the threshold before q but must continue to q. It does not create an administrative-censor term or identify the unknown post-window tail. Capacity recovery remains allowed. The first observed threshold crossing is tracked separately for the RUL target.

The one-step conditional mark score is for the next source-anchor transition only. If the last arrived anchor precedes query time q, that is not generally the same estimand as capacity at the first source RPT after q; do not compare this score directly with query-level next-capacity baselines unless hidden intervening marks are posterior-integrated under the no-arrival condition. In the initial comparison, score conditional next-capacity only on raw-arm queries where q equals the last arrived source-stop epoch; there the next-anchor transition and next-source-RPT-after-q target coincide. Do not report this as a next-query score for sparse2 or delay7d. For those arms, report all-arm RUL/proper-risk results and sampled ordinal future-inspection trajectories; a capacity-at-calendar-horizon score would require a separately declared target and clock assumption. Convert the raw conditional capacity density to capacity-Ah units with log p(C_next|gap,C_prev)=log p(delta_log_capacity|gap,C_prev)-log(C_next); the NLL therefore includes the +log(C_next) Jacobian term. Score it separately from free-running RUL; never feed that future grid into RUL forecasts. Report cell-equal RMSE/MAE and conditional-capacity NLL with paired cell bootstrap. The likelihood of teacher-forced paths is not a substitute for query-level RUL quality.

## Preparation scope and stop rules

A fresh PREP-only GO must bind: (1) the exact 125 C1/C2 processed DataV2 cell paths and SHA-256 manifest; (2) the matching 125 RPT asset paths and hashes; (3) the frozen V18 protocol and F0 code; (4) F1 RPT feature code/assets; and (5) every package source hash. Preparation validates each path/role/hash, uses no raw archive, produces train-only anchor/suffix arrays and a receipt, and records zero fits, zero C3 reads, and zero C4 reads. The existing formal cache cannot replace every legal source anchor and must not be joined for this package.

If an expected F0 dimension, RPT source-index join, visible-prefix rule, 125-cell manifest, feature availability, or target support fails, stop and preserve a failure receipt. Unknown censor reasons do not get modeled as independent right censoring. No fit starts until root issues a separate fit GO bound to the prepared data SHA, exact four-fit budget, code hashes, and deadline.


## v2.1 addendum (2026-10-22, delegated DSH controller review)

Status: the four mandatory fixes recorded in `docs/DSH_RESEARCH_GOAL_20261022.md` are implemented before any prep/fit. No prep or fit had run at review time, so these are pre-execution code fixes, not post-hoc analysis changes. The estimand, observation model, mark family, four-fit budget, anchors and thresholds are unchanged.

1. **Runner/locks/standardization** (`fit_runner.py`): CUDA device 0 is required and pinned by the GO (`device: "cuda:0"`); the runner acquires the two shared CPU locks and the multirate GPU lock in a fixed order (CPU1 -> CPU2 -> GPU) with non-blocking `flock`, and sets 4 CPU threads. Train-only **weighted** standardization is computed from the rows each fit actually sees (internal fit: train cells only; full refit: all 125 cells), stored in model buffers (`fixed_mean/scale`, `dynamic_mean/scale`) so checkpoints are self-contained; zero-variance features keep scale 1. The internal 20% validation split is drawn from **unique contributing cell ids**, not `range(max_index+1)`. The ledger records actual optimizer steps run, the full validation history, best step, and a normalization hash.
2. **Proposal-order truncation** (`rollout.py`): every proposal carries a global serial; accepted paths are stored by serial and the final `n_samples` are taken in **proposal order**, never completion order. `selected_proposal_serials` is returned for audit, and `synthetic_check.py` exercises out-of-order completion plus the pure selection rule.
3. **Epoch precision** (`rollout.py`): proposal times and event times are float64 (at 1.6e9 s float32 quantizes to ~128 s); only model inputs/outputs are float32. `epoch_dtype` is reported by every forecast.
4. **Predeclared zero-fit controls** (`rollout.py`, `model.py`): `condition_on_no_arrival=False` switches off the no-extra-due-report conditioning; `fixed_gap_weeks=...` fixes the gap and draws the capacity increment from the **mixture posterior p(component|gap)** with the bivariate conditional mean/sd (joint variant) instead of overwriting the gap with an unconditional draw. Both controls are exercised in `synthetic_check.py`.

All fixtures in `synthetic_check.py` pass with zero data reads and zero fits (`SELF_CHECK` output is stored in the run/prep receipts and the review log).
