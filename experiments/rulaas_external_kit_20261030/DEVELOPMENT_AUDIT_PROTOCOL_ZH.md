# KIT 第二版开发工况：数据与时间语义审计

读取数据前已固定 60 个开发工况和 16 个封存工况；每工况三个电芯。压缩容器的镜像与官方归档 MD5 一致，所需容器与官方 BagIt 清单逐项一致。只打开开发工况的 180 个 EOC 文件，绝不打开封存工况或 P000_0 副实验文件。后者是原电芯短期迁移测试，不是额外独立电芯。

本次只审计输入支持与时间语义，**不产生 EOL 或 RUL 训练标签，不拟合模型**。依据 [作者绘图代码](https://raw.githubusercontent.com/energystatusdata/bat-age-data-scripts/main/plot_result_data_comparison.py) 的 check-up 放电容量筛选，读取 `cyc_condition=2`、`cyc_charged=0`、`cap_aged_est_Ah` 有效的候选记录；保留所有候选，统计每次 `num_cycles_checkup` 的记录数量、时间顺序、时间戳来源、容量估计缺失和候选的起止 SoC，不能事后按寿命结果挑记录。

`timestamp_s` 是放电结果记录的时间，并非已观测到的报告送达时间；`timestamp_origin` 有准确、估计、插值、外推及错误等类别。`cyc_duration_s` 可能不含暂停，不能假定简单相减即真实采样起始时刻。`cap_aged_est_Ah` 是估计容量，不能等同直接测得的真实故障；缺失值不填造。数据作者记载部分电芯因安全问题提前停机，这类终止可能是信息性删失或竞争风险，不能一律按随机丢失解释。

预算：最多读取 180 个明确列在开发组的 EOC 电芯文件，最多 400,000,000 未压缩字节；0 拟合、0 模型预测、0 个封存组或副实验电芯文件、0 原项目 C3/C4。保存开发候选记录、每电芯统计及来源校验；任何成员路径不符合既定工况角色或输入散列不符立即停止。下一阶段须先据本审计冻结容量事件、时钟和不可观测反馈假设，再决定能否开展有限模型对照。
