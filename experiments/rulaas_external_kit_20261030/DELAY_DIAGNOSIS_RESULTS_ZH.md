# KIT 危险窗口漏报：报告延迟与已采样信息的诊断

## 结果

在排队实验的同一批 40 个电芯、1,720 个共同周度查询上，额外构造两个信息参考：已采集结果假设**即时可见**，以及只假设**固定 14 天送达且无处理队列**。两者与排队策略使用相同的初始容量、两点斜率和寿命定义，但没有承担同样的处理站资源约束。

| 信息可见条件 | 已观察事件电芯的 MAE，周 | 四周 TP / FP / TN / FN | 完全漏掉四周窗口的事件电芯 |
| --- | ---: | ---: | ---: |
| 假设采样后即时可见 | 3.112 | 61 / 24 / 1033 / 5 | 0 / 17 |
| 假设 14 天送达、无队列 | 3.716 | 55 / 29 / 1028 / 11 | 0 / 17 |
| 固定排队规则，1 台处理站 | 3.740 | 55 / 29 / 1028 / 11 | 0 / 17 |
| 固定排队规则，2 台处理站 | 3.716 | 55 / 29 / 1028 / 11 | 0 / 17 |

66 个可判定事件前阳性查询逐条对齐后：排队条件的 **11 次漏报**中，6 次在即时可见参考下会触发提示，另外 5 次在两种条件下均漏报；没有出现“排队时提示、即时可见时漏报”的阳性查询。固定 14 天且无队列参考与排队条件的 66 次阳性判断完全相同，说明本次多出的 6 次漏报在这些固定模拟条件下与报告可见时间有关，并非再增加的排队时间造成的可见变化。

这并不证明真实服务中等待一定造成相同损害。即时可见参考没有站点或送达约束，**不属于同资源可部署策略**；两点外推对较新的信息也不保证始终更准。此处记录越阈是定期检查所得结果，不是精确连续物理失效。数据、工况和结局此前已用于开发，不能视为独立验证。

## 事后按工况观察

所有 11 次排队漏报只涉及 P052 和 P076 两个工况。6 次可由即时可见参考改变的查询涉及 4 个电芯，排队条件下最新可见样本年龄中位数为 **3.26 周**，即时条件下为 **0.27 周**。其余 5 次在两种条件下都漏报，涉及 5 个电芯；两种条件使用的最新样本年龄中位数均约 **2.26 周**。

这些分组是看到结果后的描述，不用于调整阈值或宣称特定工况的显著差异。它们提示后续需要同时研究报告延迟和检测间隔，但不能据此认定具体退化机理。对 3,440 条新参考查询使用独立的按时间推进程序重建，前缀、已有队列目标、四周混淆矩阵及逐次交叉计数均通过；没有新模型训练或队列派发，C3/C4 和 16 个封存确认工况读取均为 0。

## 真实时间数据线索

目前核查到的 KIT EOC 数据有容量记录时间，但没有本实验所需的独立服务请求、处理完成和报告送达日志。公开的 [Open Mobile Battery Telemetry Dataset](https://github.com/souzamonteiro/Open-Mobile-Battery-Telemetry-Dataset) 项目说明列有相对时间戳，并说明不公开原始服务器日志；其公开说明未证实同时具备本研究需要的三段服务时间和独立寿命终点。

[Tesla Fleet Telemetry 官方字段文档](https://developer.tesla.com/docs/fleet-api/fleet-telemetry/available-data)说明车辆可发送电池等遥测字段；其项目的一个[公开问题样例](https://github.com/teslamotors/fleet-telemetry/issues/336)同时展示了记录创建时间与接收时间字段。后者是单条用户问题样例，并非已取得的电池寿命队列数据，也未证明字段时钟语义、覆盖率或失效标签可用。当前检索范围内尚未核实可直接使用、同时具有请求/采样/送达和电池寿命终点的公开数据。

下一步应在不打开封存工况的条件下，针对同两工况内“最新样本相同但仍漏报”的查询检查退化速率变化与前缀可辨识性；同时继续寻找可核验真实服务时间的数据，保留已判定失败的固定排队规则。
