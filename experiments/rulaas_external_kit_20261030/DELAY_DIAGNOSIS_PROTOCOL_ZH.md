# 危险窗口漏报：固定记录可见时间诊断

问题：已有一台/两台站排队回放中 66 个可判定事件前四周查询各有 11 个漏报；如果相同的已采集容量记录更早可见，哪些漏报会改变？

复用已独立复核的 40 电芯、43 个共同周度查询和全部队列预测。只额外计算两种信息可见性参考：`immediate` 在查询 `q` 使用采样时间 `s <= q` 的已采集容量；`delay14_noqueue` 使用 `s + 14 天 <= q` 的已采集容量。两者使用与排队实验相同的初始容量、两点线性外推、非负斜率回退，不训练模型。分别将两种参考与已保存的一台/两台站 `pending_value` 结果对齐，共同查询和目标严格一致；报告事件电芯 MAE、四周 TP/FP/TN/FN、电芯级漏报、预测可见样本滞后、逐事件查询在各可见性条件下的提示/漏报交叉数。

每条参考预测仅使用指定截止前的前缀，且检查排队可见的最后两个采样时刻分别属于该参考可见前缀；早到报告提供更多信息并不保证两点斜率一定更准。即时可见和无队列参考没有计入有限处理站资源，不能被包装成同资源策略改进或可实现收益；这不是改变并重试已失败的排队规则。先保存全部参考预测，再从既有队列记录复制标签并核对。

预算：固定 3440 条新参考查询，0 个全局/局部拟合、0 个新排队派发、0 次 C3/C4、0 次封存确认工况读取；固定输入/源码哈希与查询键，任何键、目标、前缀或计数不一致立即失败。结果为此前使用过的开发数据上的描述性机制诊断，不做显著性、独立泛化或真实报告延迟声明。
