# KIT 已测容量报告的在途感知排队：固定开发回放

## 问题和范围

当电池容量检测记录成批出现、结果处理能力有限且处理后还要等待报告送达时，能否利用“新报告对两点斜率输入的预计新鲜度增量”和当前寿命紧迫程度，获得比先进先出、最陈旧信息优先、最早预计终点优先更好的预测，同时不损害事件预警和事件报告延迟？这是新队列排序探针；不同于已停用的在途**接纳/拒绝**规则，本次所有策略处理相同任务，不丢弃任务，亦不重启该失败配置。

源数据为已使用的 KIT 内部开发保留工况，16 个外部确认工况和原 C3/C4 保持封存。数据作者说明 EOC 数据在充放电操作后收集：[Scientific Data，Data Records：Post-processed end of charge data](https://www.nature.com/articles/s41597-024-03831-x)。故本回放将该记录时间视为容量样本已产生的时间 `s`，再模拟报告处理与送达；这里的“站”是**假设的报告处理服务**，不能声称测量被实际取消或报告延迟确实如此。

## 人口、资源和时间

固定起点为已选的第 100 天、终点为第 400 天。只按起点可见的信息选择电芯：初始容量记录可用且其 check-up 编号不大于 1、起点前至少有两条已送达的容量记录、这些已送达记录中尚未观察到初始容量 80% 的越阈；不能按未来事件或最终随访选择。该规则产生的工况和电芯保留计数；已实际发生但尚未送达的事件仍纳入。

种子信息假设：`s <= 起点 - 14 天` 的历史结果已经送达；其余起点前已采集的记录设为已完成处理、将在 `s + 14 天` 到达的暖启动在途报告，所有策略相同。研究期内每条真实 EOC 记录生成一个处理任务，采样时才入队；队列非抢占、每任务固定占站 3 小时、处理后再固定延迟 14 天送达，分别使用 1 台和 2 台站。3 小时是模拟值，参考先前观察到的容量放电时长中位约 2.62 小时取整，**不是实测的报告处理时长或完整检测成本**。14 天同样是假设。所有任务保留并最终处理；越阈后仍保留已记录的任务，反映无替换干预的追溯回放。各策略同一站数下使用同一任务集合和相同固定处理量，不声称节省了检测成本。

每 7 天在同一个时间网格为所有选入电芯生成查询；调度器和预测器只看已送达内容及已采样任务/在途报告的时间与状态。`s <= 开始处理 <= 处理结束 <= 报告送达 <= 查询` 才能影响该次查询。报告可乱序，按采样时间重建已送达容量前缀；使用最近两条已送达容量和相同 80% 阈值外推预计终点，非负斜率使用原先训练工况成熟事件中位寿命回退。预测终点早于当前时允许负剩余时间，不截断。越阈后的真实状态不传入调度器；报告中第一次看到越阈后，记录为已检测，仍按预先设定处理剩余任务。

## 预先固定的四种排序

同一时刻先处理所有已有到达、完工和报告，再对空闲站连续派发，所有策略工作保守、服务时间相同。平分时按样本时间及电芯 ID 确定顺序。

1. `fifo`：样本时间最早优先。
2. `oldest_info`：当前最新已送达样本最旧的电芯优先。
3. `earliest_eol`：由最近两条已送达容量外推的预计越阈时间最早优先；已检测越阈电芯排在尚未检测者之后。
4. `pending_value`：对等待任务，先用当前已送达时间以及**将在该任务预计报告到达前或同时到达**的在途样本时间，形成最后两个有效样本时刻；比较纳入该任务采样时刻前后，这两个时刻平均值能提前多少。增量非负、仅依赖时间与已知在途状态。再乘 `1 / (1 + max(预计终点 - 预计报告到达, 0) / 4 周)`；已检测越阈电芯的权重为零。得分最高者优先。任务尚未送达的容量数值不能用于评分。

这是一项可证伪的服务机制探针，不声称信息价值排队或剩余寿命紧迫调度是首创。相关工作已讨论利用预测不确定性安排检测，见 [Kim 等，2022，Section 3.1](https://www.sciencedirect.com/science/article/pii/S0951832022000667)。

## 固定评价与停止条件

预测先为所有共同网格查询生成，再由独立保存的观察事件和最后随访给评价标签。主要误差只在未来确有记录越阈的电芯、越阈前共同查询上计算：先对电芯的查询误差取均值，再对电芯等权；两种站数的差值按电芯等权平均。四周标签为后来记录事件、足够长的阴性随访或未知；未知不填阴性。另报告事件前窗口没有任何 `RUL <= 4 周` 预警的电芯数、阴性查询误报数、首次可见越阈报告的事件检测延迟、所有电芯逐组损害、被处理及在途任务数、最大排队与各策略在各时刻占站轨迹。

预定开发通过要求：候选相对三个参考的事件电芯 MAE 均至少下降 5%，三个配对工况组 Bootstrap 区间的上界均低于 0（10000 次、seed 42、三项 Bonferroni 修正，双侧 98.333%）；各站数场景中漏报事件电芯数、误报查询数及已观察事件的平均检测延迟均不高于任一参考，且 MAE 在任何一个场景不得比任何参考增加超过 5%。只要一项不满足即 `NO_GAIN_FIXED_QUEUE_VALUE`；所有不利结果保留。

预算：固定 40 个基于起点可见数据选入的电芯（若实际计数不一致则失败）、固定 470 个研究期采样任务/每策略、2 个站数、4 个排序策略，最多 3760 次任务派发、13760 条网格预测，无任何预测模型拟合，无 GPU。固定输入/源码哈希及 seed 后运行；核对全部排序中的任务守恒、因果时间和各策略逐时相同占站资源，再独立重算。0 次 C3/C4、0 次封存确认工况读取。

事件定义依旧是容量首次记录越阈而非连续物理失效；数据和结局已用于开发、截止回顾性、信息性删失可能存在，事件工况少。任务采样本身已发生，队列和送达延迟是模拟设定，因此不能声称真实车队成本、实际检测干预或论文达标；目标验证仍需独立工况和真实服务过程。
